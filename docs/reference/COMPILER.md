# AntiOS 3.0 Project Environment Compiler (`docs/reference/COMPILER.md`)

**Document**: `docs/reference/COMPILER.md`  
**Status**: CANONICAL REFERENCE  
**Version**: 3.0.0-STAGE1  
**Module**: `framework/compiler/`  
**CLI Command**: `antios compile [--path <PROJECT>] [--check] [--json] [--force]`

---

## 1. Purpose & Product Thesis

AntiOS 3.0 is an **Agent-Native Project Environment Compiler and Governance Plane for Google Antigravity**. Antigravity is the autonomous execution substrate; AntiOS does not run as a background daemon, vector database, or custom agent runtime.

The compiler deterministically transforms an arbitrary target repository into a compact, navigable, and stateful native agent environment:
```
TARGET REPOSITORY
        ↓
Project Inspection (bounded, zero-dependency)
        ↓
Deterministic Project Intelligence
        ↓
Compact Native Agent Environment (.agents/routes.json, AGENTS.md, ast_outlines.json)
```

---

## 2. CLI Usage

The compiler is accessed via the standard AntiOS CLI entrypoint:

```bash
# Compile the target repository (defaults to current working directory)
antios compile

# Compile an explicit project directory
antios compile --path /path/to/project

# Dry-run validation (preview emitted files without mutating filesystem)
antios compile --check

# Machine-readable JSON output for automated pipelines
antios compile --json

# Force overwrite of user-authored AGENTS.md
antios compile --force
```

### Exit Codes
- `0`: Successful compilation or validation check passed.
- `1`: Target path invalid, unhandled filesystem error, or verification failure.

## 3. Output Schema & Contracts

At successful compilation, the compiler emits three primary artifacts into the target repository:

### 3.1 Subsystem Route Map: `.agents/routes.json`
- **Schema**: `https://antios.dev/schemas/v3/routes.json`
- **Role**: Provides the shortest deterministic path from user intent to authoritative source code and proving test commands, eliminating exploratory `grep_search` overhead.
- **Fields**:
  - `project_id`: Stable identifier derived from repository manifests or folder name.
  - `subsystems`: Dictionary mapping subsystem name to:
    - `root_dir`: Relative path with POSIX forward slashes (`/`).
    - `description`: Single-sentence domain summary.
    - `entrypoint`: Primary implementation file path.
    - `test_suite`: Subprocess command array (e.g. `["python", "-m", "unittest", "tests.test_auth"]`).
    - `capabilities`: Key operation verbs implemented by the subsystem.
    - `invariants`: Constitutional invariant tags (`INV-01`, `INV-10`).

### 3.2 Turn-0 Constitution: `./AGENTS.md`
- **Role**: Ingested automatically by Antigravity on session start (Turn 0).
- **Hard Constraints**:
  - Strictly $\le 40$ lines.
  - Strictly $< 250$ tokens.
- **Contents**:
  - Canonical AntiOS generation signature (`<!-- Generated by AntiOS Project Compiler -->`).
  - Turn-0 Orientation directives.
  - Subsystem index referencing `.agents/routes.json`.
  - Verification law (`tests/run_all.py` or primary test suite).
  - Protected boundary declarations (`.agents/`, `antios.config.json`, `.git/`).

### 3.3 AST Symbol Outlines: `.agents/cache/ast_outlines.json`
- **Schema**: `https://antios.dev/schemas/v3/ast_outlines.json`
- **Role**: Caches exact class and function signatures mapped to 1-indexed line ranges for precision inspection via `view_file`.

---

## 4. AST Outline Semantics & Non-Faking Guarantee

- **Python Standard Library Only**: Uses Python's built-in `ast` module.
- **Exact Line Ranges**: Extracts 1-indexed `start_line` and `end_line` for all classes, methods, and functions.
- **Signature Extraction**: Formats parameter names, type annotations, return types, and async flags.
- **Unsupported Languages**:
  - The compiler **never synthesizes fake AST data** for languages without standard-library parser support (TypeScript, Rust, Go, etc.).
  - Non-Python files are flagged with `extractor: "unsupported"` and `confidence: 0.0`.

---

## 5. Artifact Ownership & User Protection

- **Ownership Signature**: Emitted `AGENTS.md` files include `<!-- Generated by AntiOS Project Compiler -->`.
- **User Content Protection**: If an existing `AGENTS.md` does not contain the canonical signature, compilation preserves the user's file and emits `AGENTS.generated.md` instead, issuing a warning.
- **Force Overwrite**: Supplying `--force` overrides the protection and overwrites `AGENTS.md`.

---

## 6. Deterministic Compilation & Portability Guarantees

1. **Zero Machine-Local Absolute Paths**: All paths in generated JSON and Markdown use relative POSIX forward slashes (`/`). No drive letters (`C:`) or user home directory prefixes are emitted.
2. **Stable JSON Serialization**: JSON outputs are formatted with `sort_keys=True`, 2-space indentation, and LF line endings (`\n`).
3. **No Volatile Timestamps**: Generated files contain zero system timestamps, ensuring identical repository state produces byte-for-byte identical output (0 Git diff).
4. **Idempotence**: Running `antios compile` multiple times on an unchanged repository creates zero file mutations.

---

## 7. Supported Ecosystems & Limitations

### Supported Ecosystems
- **Python**: `pyproject.toml`, `setup.py`, `setup.cfg`, `requirements.txt`, `Pipfile`, `tests/`.
- **TypeScript / JavaScript**: `package.json`, `tsconfig.json`, `src/`, `tests/`.
- **Rust**: `Cargo.toml`, `src/`, `tests/`.
- **Go**: `go.mod`, `go.sum`, `main.go`.
- **Polyglot / Mixed**: Repositories containing multiple languages are detected and mapped cleanly.

### Limitations
- AST symbol outline extraction is restricted to Python files in Stage 1 to maintain zero third-party dependencies.
- Multi-repo workspaces must run `antios compile` within each repository root independently.
